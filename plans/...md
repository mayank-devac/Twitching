1. Kick tokens can show up unhidden in launcher messages

What a "redactor" is: a function that replaces secrets in text with [redacted] before the text is shown anywhere.

There are two redactors, and they hide different lists of secrets.

The server keeps its list up to date. When it creates a new Kick login token, it adds that token (server/index.ts:161-163):

mintedKickTokens.push(live);
redactKnown = redactor([...privateValues, ...mintedKickTokens], root);

The launcher (the start_stream script) builds its redactor once at startup and never updates it (scripts/stream.ts:110):

const clean = redactor(privateValues, root);

How this could leak a token:
1. The server refreshes Kick and gets a new token
2. The server hides it ✅ — the launcher doesn't know it exists ❌
3. An error message containing that token reaches the launcher
4. The launcher prints it to your terminal or log unhidden

Your decision: this is the first step of plans/A9-shared-server-wiring.md: one shared list of secrets that both sides use. It's small, and I'd do it next.
